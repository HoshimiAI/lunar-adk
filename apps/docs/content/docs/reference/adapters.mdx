## `createOpenAIModelProvider(options)`

Package: `@lunar/provider-openai`

Required option:

- `model`: the OpenAI model name.

Optional options are `id`, `apiKey`, `baseURL`, `organization`, `project`,
`headers`, `name`, `fetch`, and `capabilities`. It returns a foundation
`ModelProvider` with tool calling, structured output, and streaming enabled by
default.

```ts
const model = createOpenAIModelProvider({
  model: 'gpt-5-mini',
  apiKey: process.env.OPENAI_API_KEY,
});
```

## `createAISDKModelProvider(options)`

Package: `@lunar/provider-ai-sdk`

Accepts `id`, an AI SDK `LanguageModel`, and optional capability overrides. It
maps AI SDK text, tool calls, usage, and abort signals to the Lunar provider
contract.

## `createSqliteStores(database?)`

Package: `@lunar/storage-sqlite`

Accepts a SQLite path or Bun `Database`, defaulting to `lunar.db`. Returns:

- `database`: the opened database;
- `runStore`: durable run storage;
- `sessionStore`: durable session storage;
- `workflowStore`: durable workflow-run storage;
- `close()`: closes the database.

The package also exports `SqliteRunStore`, `SqliteSessionStore`,
`SqliteWorkflowStore`, and `SQLITE_SCHEMA_VERSION`.

## `createSqliteMemoryProvider(database?)`

Package: `@lunar/memory-sqlite`

Creates a durable `MemoryProvider` backed by a Bun SQLite database. It
persists memory records and implements the foundation provider's substring
retrieval and limit behavior. Pass the provider as `memory` to
`createRuntime()`.

## `createHttpStores(options)`

Package: `@lunar/storage-http`

Creates remote run, session, and workflow stores backed by a JSON HTTP service.
The provider uses `PUT /v1/{resource}/:id` for idempotent saves and
`GET /v1/{resource}/:id` for reads. Missing records return `undefined`.

Options include `baseUrl`, an optional bearer `token`, custom `headers`,
`timeoutMs`, `maxAttempts`, and `retryDelayMs`. Reads and idempotent writes
retry transient network, timeout, rate-limit, and server failures.

## `createBunSqlStores(options)`

Package: `@lunar/storage-bun-sql`

Creates the same storage bundle using Bun.SQL. Supported dialects are
`sqlite`, `postgres`, and `mysql`; MariaDB uses the MySQL dialect. The
`connection` can be a Bun SQL connection URL or an existing `SQL` client.

## `createMongoStores(options)`

Package: `@lunar/storage-mongo`

Accepts an application-provided Mongo database object and maps runs, sessions,
and workflow runs to collections using `replaceOne(..., { upsert: true })`.
The package intentionally does not own a MongoDB SDK dependency.

All storage adapters implement revision-aware saves. HTTP adapters send the
expected revision as `If-Match` and create-only writes as `If-None-Match: *`;
a compatible remote service must reject stale writes with `409` or `412`.
Adapters expose `capabilities.atomicRunSession` so applications can distinguish
atomic bundles from stores that persist runs and sessions separately.

## `@lunar/observability-otel`

The optional observability package exports `createConsoleExporter()` and
`createOTLPExporter({ endpoint, headers, serviceName })`. Pass exporters through
`createRuntime({ observability: { exporters } })`. Telemetry captures metadata
only by default; set `captureContent: true` explicitly to include prompts,
outputs, and tool inputs.
