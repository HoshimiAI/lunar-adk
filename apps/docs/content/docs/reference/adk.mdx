The stable facade re-exports the APIs most applications need, including memory,
workflows, and plugins. Evaluation APIs remain experimental and are exported
from `@lunar/adk/experimental`.

| Export | Purpose |
| --- | --- |
| `createRuntime` | Compose agents, stores, events, and workflows |
| `defineAgent` | Create a model-backed agent |
| `defineTool` | Create a typed tool with validation and execution |
| `defineModelProvider` | Mark a provider as a foundation model provider |
| `createSession` | Create an empty session |
| `defineWorkflow` | Create a resumable workflow |
| `definePlugin` | Define a versioned runtime extension bundle |
| `createMemory`, `createInMemoryProvider`, `MemoryRegistry` | Configure optional long-term memory |
| `InMemoryRunStore`, `InMemorySessionStore`, `InMemoryWorkflowStore` | Development stores |
| `AgentRunError`, `WorkflowApprovalRequired` | Execution and approval errors |

## `createRuntime(config?)`

Returns a promise for a `RuntimeHandle`. Configure optional `plugins`,
`runStore`, `sessionStore`, and `workflowStore`; omitted stores are in-memory.
Provider factories such as `createSqliteStores()` and `createHttpStores()`
return compatible bundles for local and remote deployments.

Pass a complete `storage` bundle to compose all three stores at once. Configure
one or more memory providers with `memory`; `ownsMemory: true` makes
`runtime.shutdown()` close them. Set
`ownsStorage: true` when the runtime should close that bundle from
`runtime.shutdown()`; application-managed bundles should leave it unset. A
bundle cannot be mixed with individual store overrides.

Persisted runs, sessions, and workflow runs carry revisions. Store updates can
reject stale revisions with `StorageConflictError`, allowing multiple runtime
instances to detect lost-update races.

The handle exposes `run`, `stream`, `supportsStreaming`, `steer`, `approve`,
`reject`, `cancel`, `getRun`, `getStoredRun`, `getSession`, `on`,
`getMemoryProvider`, `registerAgent`, `registerWorkflow`, `runWorkflow`, `getWorkflowRun`,
`resumeWorkflow`, and `cancelWorkflow`.

### Runtime methods

- `run(agentName, input, options?)` executes an agent and returns output plus
  its run record.
- `supportsStreaming(agentName)` reports whether the registered model streams.
- `stream(agentName, input, options?)` yields runtime stream events.
- `steer(sessionId, instruction)` updates an idle session or interrupts its
  active run and returns continuation IDs.
- `approve(runId, approvalId)` resumes an approval-gated tool call.
- `reject(runId, approvalId)` rejects a pending tool call.
- `cancel(runId)` cancels an active run, returning `undefined` when not found.
- `getRun(runId)` reads the in-process run map; `getStoredRun(runId)` reads the
  configured store.
- `getSession(sessionId)` reads a stored session.
- `getMemoryProvider(id?)` returns the selected custom memory provider.
- `on(event, handler)` subscribes to an event and returns an unsubscribe
  function.
- `registerAgent(agent)` and `registerWorkflow(workflow)` add runtime behavior.
- `runWorkflow(name, input?)` starts a workflow.
- `getWorkflowRun(id)` reads a workflow run.
- `resumeWorkflow(id, approvalId?)` resumes a waiting workflow.
- `cancelWorkflow(id)` cancels a workflow and returns its final record.

## `defineAgent(config, eventBus?)`

Accepts `name`, `model`, optional `systemPrompt`, `tools`,
`maxToolRoundtrips`, `retryPolicy`, `maxContextTokens`, and opt-in `memory`.
Optional `hooks` provides async `beforeModel`, `afterModel`, `beforeTool`, and
`afterTool` callbacks. Hooks receive read-only execution context and run in
sequence at their lifecycle point; a thrown error fails the agent run. Hooks
observe inputs and results and do not replace them.
Memory options select a provider, namespace, metadata filter, retrieval limit,
and whether completed conversations are stored. Returns an `Agent`
with `run(input, options?)`.

```ts
defineAgent({
  name: "assistant",
  model,
  hooks: {
    beforeModel: ({ runId, round }) => logger.info({ runId, round }, "model call"),
    afterTool: ({ toolCall, result }) => audit({ tool: toolCall.name, result }),
  },
});
```

## `defineTool<Input, Output>(tool)`

Returns the supplied tool contract. A tool contains `name`, `description`, a
schema with `parse()` and `toJSONSchema()`, an optional approval permission, and
an `execute(input)` function.

## `defineWorkflow(config)`

Accepts `name` and either an async `run(context)` function or a declarative
`root` step tree. `version` defaults to `"1"`.

## `definePlugin(plugin)`

Defines a stable, versioned extension bundle. Plugins can register agents,
tools, workflows, memory providers, evaluators, event handlers, commands, and
schemas, and policy rules through `PluginContext`; optional `start()` and
`stop()` hooks follow runtime lifecycle. Configure plugin bundles through
`createRuntime({ plugins })` and inspect their status with
`runtime.listPlugins()`. Plugin rules are appended after application
`policyRules` in dependency order, so application rules take precedence.

## Common types

The facade exports `Agent`, `AgentConfig`, `AgentHooks`, `AgentRunOptions`, `AgentRunResult`,
`Tool`, `ToolResult`, `Plugin`, `PluginContext`, `PluginManifest`,
`PluginPermissions`, `ModelProvider`, `ModelResponse`, `ModelStreamPart`,
`Run`, `Session`, `Workflow`, `WorkflowRun`, and their related status and store
types. See the concept guides for behavior and examples.

## `@lunar/adk/experimental`

This subpath exposes the currently experimental evaluation surface:

- `defineEvaluator` and the `Evaluator` and `EvaluationScore` types;

Plugin exports remain available from this subpath for source compatibility, but
are deprecated. Import them from `@lunar/adk` instead.

For all underlying helpers and subpath modules, use the
[Foundation reference](/docs/reference/foundation).
