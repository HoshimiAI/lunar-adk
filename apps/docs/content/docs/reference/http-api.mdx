---
title: "HTTP API: Elysia"
description: Use the reference Bun HTTP service and its SSE stream
---

The example service in `apps/elysia` exposes a JSON API backed by an assistant
agent. Start it with `bun --cwd apps/elysia run dev`; the default base URL is
`http://localhost:3000`.

The service uses local SQLite storage by default. Set `STORAGE_PROVIDER=http`
with `STORAGE_HTTP_BASE_URL` to use a remote storage provider.

The adapter exports two factories:

- `createApp(runtime)` builds the Elysia app around an existing
  `RuntimeHandle`, which is useful for tests and custom deployments.
- `createDefaultApp()` creates SQLite storage, configures the OpenAI assistant,
  installs the example tools, and closes storage from the app shutdown hook.
- `createAppWithBetterAuth(runtime, options)` mounts a Better Auth handler and
  adapts its session to a Lunar principal through `mapPrincipal`.

Set `recoverWorkflowsOnStartup: true` in either app factory to resume persisted
running workflows before the app is returned. Register agents and workflows on
the runtime first; app creation waits for recovery to finish.

All JSON requests use `content-type: application/json`. Input strings must be
1–32,000 characters, and steering instructions must be 1–4,000 characters.

## Health

`GET /health` returns `{ "name": "lunar-elysia", "status": "ok" }`.

## Run an assistant

`POST /run`

```json
{ "input": "Explain why Bun is useful", "sessionId": "optional-session-id" }
```

Returns `{ output, runId, sessionId, status, pendingApproval, usage, metrics }`.
`usage` contains `inputTokens`, `outputTokens`, and `totalTokens`. `metrics`
contains whole-run `durationMs` and `outputTokensPerSecond`; when model trace
timing is available, it also includes `modelDurationMs` and
`modelOutputTokensPerSecond`, excluding tool and workflow time. Use the returned
session ID to continue a conversation.

## Stream an assistant

`POST /run/stream` accepts the same body and returns `text/event-stream`. The
SSE event names are:

- runtime lifecycle event names such as `run.started` and `tool.completed`;
- `text.delta` with `{ runId, text }`;
- `stream.completed` with output, run, session, status, approval, usage, and
  throughput metric data;
- `stream.interrupted` with continuation IDs;
- `stream.error` with `error`, and optional `runId` and `code`.

The endpoint returns `501` with `STREAMING_UNSUPPORTED` when the configured
model cannot stream.

## Runs and approvals

| Method | Route | Result |
| --- | --- | --- |
| `GET` | `/runs/:id` | Stored run plus calculated `usage` and `metrics`; `404` if absent |
| `POST` | `/runs/:id/cancel` | Cancelled run; `404` if absent |
| `POST` | `/runs/:id/approve` | `{ runId, status, output, pendingApproval }` |
| `POST` | `/runs/:id/reject` | Updated run |

Approval requests use `{ "approvalId": "..." }`. Invalid or no-longer-pending
approvals return `409`.

## Sessions and steering

`GET /sessions/:id` returns the session plus aggregate `usage` and `metrics`
for its persisted runs, or `404`. Session totals include `inputTokens`,
`outputTokens`, and `totalTokens`; its throughput values use the summed runtime
and model durations of completed runs rather than idle time between turns.

`POST /sessions/:id/steer` accepts `{ "instruction": "..." }`. It returns
`{ sessionId, steered: true }` when no run is active, or `202` with
`{ status: "accepted", interruptedRunId, continuationRunId, sessionId }` when
an active run is interrupted.

## Curated memory

Memory endpoints are available only when the application configures both an
auth provider and a memory provider. They are tenant-scoped and require the
stated principal permission:

| Method | Route | Permission | Result |
| --- | --- | --- | --- |
| `POST` | `/memories` | `memory:write` | Creates a record with `content`, a future ISO `expiresAt`, and optional `namespace` and `metadata` |
| `POST` | `/memories/upload` | `memory:write` | Accepts multipart `file` (UTF-8 text, up to 5 MiB) and future ISO `expiresAt`; chunks it into memory records and embeds each chunk when embeddings are configured |
| `GET` | `/memories` | `memory:read` | Returns a paginated memory page; accepts optional `namespace`, `cursor`, and `limit` query parameters |
| `DELETE` | `/memories/:id` | `memory:delete` | Deletes a record owned by the current tenant |

Create requests return `201`. Missing memory configuration or records return
`404`; malformed or expired create input returns `422`; missing permission
returns `403`.

## Workflows

| Method | Route | Body / result |
| --- | --- | --- |
| `POST` | `/workflows/:name/run` | Optional `{ input }`; returns workflow run ID and status |
| `GET` | `/workflow-runs/:id` | Returns the workflow run or `404` |
| `POST` | `/workflow-runs/:id/cancel` | Returns the cancelled run |
| `POST` | `/workflow-runs/:id/resume` | Optional `{ approvalId }`; resumes approval |

Unknown workflows and missing workflow runs return `404`. A workflow that is
waiting for approval returns its pending approval in the run response.

## Errors

Validation errors return `422` with `{ error: "Invalid request", details }`.
Missing resources return `404`; cancelled agent runs return `409`; unexpected
agent errors return `500` with the affected `runId`. When authentication is
configured, every route except `/health`, `/readyz`, and the configured auth
route prefix requires a recognized principal.
